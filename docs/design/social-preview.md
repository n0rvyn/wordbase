# Social link previews

The homepage now shares as **我做的东西 — norvyn** with **做些自己想用的应用，写点最近在想的事。偶尔也聊一聊。** The English route uses **Things I make — norvyn** and **Apps I want to use, things I’m thinking about, and the occasional conversation.** These are static page metadata; no client-side script is required for a crawler to see them. The visible homepage design and established URLs are preserved.

The first-party image is `/social/norvyn-v2.png` (1200 × 630). Its wordmark, orange asterisk and domain all fit inside the central square, so the important artwork survives a square thumbnail crop. `/social/norvyn-square-v2.png` provides an actual 600 × 600 alternative. The old `/og-image.png` URL still works and contains the updated design. The artwork uses the existing Wordbase font and public palette; no external project artwork or invented personal photo is used.

`pnpm --filter api exec tsx ../../scripts/render-site-social.mts` (from the repo root with the supported project runtime) deterministically regenerates the site images. `src/lib/og-image.ts` also generates centered, square-safe post and app cards. App cards use the actual iOS/macOS/Web platform and compact product name. Their content-cache keys include the renderer version and platform. Existing authored post covers are preserved; podcast previews prefer real show/episode artwork. Generic section pages retain their own title/description rather than adopting the homepage title.

The shared head includes absolute Open Graph image URLs, truthful dimensions/type for generated images, alt text, locale and canonical URL. The first default image is the wide card; the square alternative follows with its own dimensions. A legacy `image_src` link points to the square default. Twitter/X retains an explicit large-image card and image alt text. Authored cover dimensions are left unspecified when unknown. The structured fields and ordering follow the [Open Graph protocol](https://ogp.me/).

Image URLs are versioned so a client that re-reads the page can request new artwork. That does not force a platform to re-fetch cached page metadata immediately. We can verify the live HTML and PNG bytes, but cannot promise when an existing Weixin, iMessage or social-app cached card will refresh. No WeChat JS-SDK account integration, signing service, new permissions, DNS or Caddy configuration was added. Actual platform share-sheet behavior still depends on that platform's client and cache.

Tests cover PNG dimensions, the actual pixel bounds of the key site artwork within the central square, legacy/custom image handling, app-platform cache identities and rendering. Live acceptance checks the Chinese/English homepage metadata, per-app/per-post/podcast metadata, image availability/content type and the versioned assets.
